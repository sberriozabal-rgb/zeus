# Prueba de la skill — 15-sep-2026

**Resultado: la skill funciona de extremo a extremo.** Generó un audio en español a través de
un backend real de VoiceStudio 0.5.2, por sus dos vías: la API REST compatible con OpenAI y el
servidor MCP. Evidencia en `cases/prueba-es-2026-09-15.mp3` (frase: «Hola, soy la voz de prueba
de VoiceStudio.»).

## Entorno

Contenedor Linux x86_64 sin GPU (4 CPU, 15 GB RAM), no el Mac del titular. El proxy del entorno
bloqueaba `huggingface.co`, `hf-mirror.com`, `modelscope.cn` y `download.pytorch.org`, así que el
modelo por defecto (`k2-fsa/OmniVoice`, 2,4 GB en Hugging Face) no se pudo descargar.

## Cómo se hizo la prueba

1. VoiceStudio clonado desde GitHub e instalado con `uv pip install --no-sources` para que PyTorch
   viniera de PyPI y no del índice bloqueado (unos 12 GB de dependencias, versión CUDA corriendo en CPU).
2. Motor alternativo `sherpa-onnx` con el modelo VITS en español `vits-mms-spa` (114 MB), descargado
   de las releases de GitHub de `k2-fsa/sherpa-onnx`, que sí eran accesibles.
3. Backend arrancado con:
   ```sh
   OMNIVOICE_TTS_BACKEND=sherpa-onnx \
   OMNIVOICE_SHERPA_MODEL=/ruta/vits-mms-spa \
   OMNIVOICE_DATA_DIR=/ruta/datos \
   .venv/bin/uvicorn main:app --app-dir backend --host 127.0.0.1 --port 3900
   ```
4. Comprobaciones con los scripts de la skill y las dos vías de generación.

## Qué se verificó

| Paso | Resultado |
|---|---|
| `scripts/check-health.sh` | `{"status":"ok","device":"cpu","version":"0.5.2"}` |
| `POST /v1/audio/speech` (model `tts-1`, `language: es`, wav) | 200 OK, WAV de 2,73 s a 16 kHz, pico 0,79, en 3,7 s |
| MCP `check_health` + `generate_speech(text, language="es")` | 7 herramientas expuestas; audio de 2,73 s en 2,4 s |
| `scripts/stop-backend.sh` | Apagado limpio |

No se pudo escuchar ni transcribir el audio en el contenedor (los modelos de reconocimiento
también viven en Hugging Face). Duración, muestreo y nivel de señal cuadran con la frase.

## Limitaciones encontradas

- **Piper en VoiceStudio no funciona tal cual.** El motor `sherpa-onnx` de VoiceStudio construye la
  configuración VITS solo con `model.onnx` y `tokens.txt`; no pasa `data_dir` (`espeak-ng-data`),
  que los modelos Piper necesitan para fonetizar. Probado en directo con sherpa-onnx y `data_dir`,
  el modelo `vits-piper-es_ES-sharvard-medium` (2 voces, 22 kHz) suena claramente mejor que MMS.
  Es un límite del código upstream, no de la skill; no se parchea aquí (ver `ORIGEN.md`).
- La voz MMS es inteligible pero robótica. En el Mac, con el modelo OmniVoice completo, la skill
  clona voces y suena mucho mejor.
- `scripts/record-reference.sh` es solo macOS (usa `avfoundation`, `say` y `afplay`); no se probó.

## Para repetirla en el Mac

Con VoiceStudio abierto (o arrancado con `scripts/start-backend.sh`), en Claude Code dentro de zeus:

> genera con omnivoice un audio en español que diga: Hola, soy la voz de prueba de VoiceStudio.

O directamente:

```sh
curl -s http://localhost:3900/v1/audio/speech -H "Content-Type: application/json" \
  -d '{"model":"tts-1","voice":"demo0001","input":"Hola, soy la voz de prueba de VoiceStudio.","response_format":"wav","language":"es"}' \
  --output prueba-es.wav && afplay prueba-es.wav
```
